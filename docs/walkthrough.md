# v2 の処理の流れ

1. `index.html` から `src/main.ts` を読み込み、CSS を適用して `mountApp` を呼ぶ。
2. `mountApp` が画面とイベントを登録する。ユーザー名の初期値は空欄で、起動時に通信や保存情報の読み出しはしない。
3. 取得フォームの送信時に前後の空白を除く。未入力ならメッセージを表示して終了する。取得中の多重送信は無視する。
4. 取得ボタン・ユーザー名・キャッシュ破棄を無効にし、読み込み状態と一覧を更新する。
5. ユーザー名を小文字化してキャッシュ識別子とする。v2 保存領域の最新1件について、識別子、保存時刻、データ形式を検証する。10分ちょうどで失効し、異なるユーザー名や破損データは使わない。
6. 有効なキャッシュがなければ `/users/{username}/repos` に `type=owner`、更新日降順、1ページ100件でリクエストする。Link の next があれば固定 API ホスト内でページ番号を増やし、最大3ページ取得する。最後にも続きがあれば上限到達を記録し、ID の重複を除く。
7. 各レスポンスのレート制限残回数とリセット時刻を読む。404、レート制限、403、その他の API エラー、通信障害、不正な応答は画面表示用のエラーに変換する。
8. 全ページ成功時だけ取得結果を localStorage に保存する。保存失敗は通知し、閲覧は継続する。キャッシュ利用時は通信せず、残回数を「取得時点」と表示する。
9. 言語の選択肢を作り、名前の部分一致・言語フィルタ・並び替えを適用してカードを描画する。カードは名前リンク、説明、言語、スター数、更新日、公開区分を表示する。0件と絞り込み結果なしを区別し、文字列は textContent で挿入する。
10. エラー時はメッセージと取得できた残回数を表示する。成功・失敗にかかわらず finally で操作を復帰し、再取得できる状態にする。
11. 検索・言語・並び替えの変更は画面内で再描画し、通信しない。キャッシュ破棄も即時通信せず、次回取得で再通信する。削除に失敗してもその画面では次回のキャッシュ利用を回避する。
