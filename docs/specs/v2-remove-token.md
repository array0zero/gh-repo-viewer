# gh-repo-viewer v2 仕様（トークン機能の除去）

## 目的

v1 で実装したトークン入力機能を完全に除去し、公開リポジトリ専用の
閲覧ツールにする。訪問者に GitHub トークンの入力を求めない状態にする。

## 背景

v1 は自分用のツールとして、非公開リポジトリの閲覧とレート制限の緩和を
目的にトークン入力欄を持っていた。公開して第三者に使ってもらう前提に
変わったため、この設計は成立しない。初見の訪問者が知らないサイトに
PAT を貼ることを期待できないため。

## 非目標

- 認証機能の代替手段（OAuth、Device Flow など）の追加
- 非公開リポジトリの閲覧
- レート制限ハンドリングの変更
- v1 で実装済みの検索・フィルタ・並び替え・キャッシュの仕様変更
- UI の再設計、見た目の改善

## 変更内容

- トークン入力欄を画面から削除する
- `localStorage` へのトークン保存・読み出しを削除する
- リクエストの `Authorization` ヘッダー付与を削除する
- `GET /user/repos`（認証あり）の呼び出しを削除し、
  `GET /users/{username}/repos` のみを使う
- `affiliation=owner` の指定を削除する
- 401 エラーのハンドリングを削除する
- キャッシュキーの識別からトークンを除外し、ユーザー名のみで識別する
- README からトークンの作成手順とスコープの記述を削除する

## 変更しないもの

- 検索、言語フィルタ、並び替え
- 10 分キャッシュとその手動破棄
- レート制限の残回数表示と超過時のエラー表示
- 404、通信エラー、0 件時のハンドリング
- ページネーション（最大 3 ページ）
- カードの表示項目

## 受入条件

1. `npm run build` が成功する
2. `npm test` が全て通る
3. 画面上にトークン入力欄が存在しない
4. `src/` 配下に `Authorization` ヘッダーを付与するコードが存在しない
5. `src/` 配下に `localStorage` へトークンを保存するコードが存在しない
6. ユーザー名を入力して取得すると、公開リポジトリ一覧が表示される
7. ユーザー名は初期値を持たず、未入力の状態で画面が開く
8. 未入力のまま取得を実行した場合、その旨のメッセージが表示され、例外が出ない
9. 取得結果が `localStorage` に保存され、10 分以内の再取得では通信が発生しない
10. 異なるユーザー名で取得した場合、前回のキャッシュが返らない
11. 残りレート制限の回数が画面に表示される
12. レート制限を超過した場合、リセット時刻を含むエラーメッセージが表示され、例外が出ない
13. 存在しないユーザー名（404）の場合、その旨のメッセージが表示され、例外が出ない
14. 通信エラーが起きた場合、エラーメッセージが表示され、画面が操作可能なまま残る
15. リポジトリが 0 件の場合、その旨のメッセージが表示され、例外が出ない
16. 非公開リポジトリに関するテストが削除されている
17. `docs/decisions/` に、トークン機能を除去した理由の記録がある
18. `docs/walkthrough.md` が変更後の処理の流れに更新されている
19. `docs/modules.md` が変更後のファイル構成に更新されている
20. README にトークンに関する記述が残っていない

## 備考

未認証のレート制限は 1 時間あたり 60 回で、発信元 IP ごとにカウントされる。
本アプリはブラウザから直接 API を呼ぶため、制限は訪問者ごとに適用される。
サイト全体で共有されるものではない。
