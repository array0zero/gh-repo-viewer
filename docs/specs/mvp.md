# gh-repo-viewer v1 仕様

## 目的

GitHub API から自分のリポジトリ一覧を取得し、言語での絞り込みと名前検索、
更新日順の並び替えができるブラウザアプリを作る。
API のレート制限を考慮し、取得結果をキャッシュして無駄な通信を避ける。

## 非目標（v1 では作らない）

- 認証・アカウント登録（トークンはユーザーが自分で用意する）
- サーバーサイド実装（すべてブラウザ内で完結する）
- リポジトリの作成・編集・削除などの書き込み操作
- Issue、PR、コミット履歴など、リポジトリ一覧以外の情報
- 他ユーザーのリポジトリ閲覧（自分のもののみ）
- OAuth フロー（トークンの手入力のみ）
- リファクタリング・既存機能の変更

## 技術構成

- Vite + TypeScript、フレームワークなし（素の DOM 操作）
- 依存は最小限。HTTP クライアントは `fetch` を使い、ライブラリを追加しない
- GitHub REST API `GET /user/repos`（認証あり）と `GET /users/{username}/repos`（認証なし）を使う
- トークンは `localStorage` に保存する。`.env` は使わない（ビルドに埋め込まれるため）
- 取得結果は `localStorage` に保存し、10 分間は再取得しない
- レスポンスヘッダー `x-ratelimit-remaining` と `x-ratelimit-reset` を読み、残回数を画面に表示する
- ページネーションは `per_page=100` で最大 3 ページまで取得する
- テストは Vitest + happy-dom。`fetch` をモックに差し替え、実際の API を呼ばない

## 画面

1 画面のみ。上部にトークン入力欄とユーザー名入力欄、
その下に検索欄・言語フィルタ・並び替えの操作列、
その下にリポジトリのカード一覧を並べる。

各カードに表示する項目。

- リポジトリ名（GitHub へのリンク）
- 説明（無い場合は空欄）
- 主要言語
- スター数
- 最終更新日（`YYYY-MM-DD` 形式）
- 公開 / 非公開の区別

## 受入条件

1. `npm run build` が成功する
2. `npm test` が全て通る
3. ユーザー名を入力して取得すると、リポジトリ一覧がカードとして表示される
4. トークンを入力した場合、非公開リポジトリも取得される
5. トークン未入力でも、公開リポジトリのみで動作する
6. 入力したトークンが `localStorage` に保存され、再読み込み後も保持される
7. 取得結果が `localStorage` に保存され、10 分以内の再取得では通信が発生しない
8. キャッシュを手動で破棄するボタンがあり、押すと次回に再取得する
9. 検索欄に文字を入力すると、リポジトリ名に部分一致するものだけが表示される
10. 言語フィルタで選択すると、その言語のリポジトリのみが表示される
11. 並び替えで「更新日順」「スター数順」「名前順」を選べ、表示順が変わる
12. 残りレート制限の回数が画面に表示される
13. レート制限を超過した場合、リセット時刻を含むエラーメッセージが表示され、例外が出ない
14. 認証エラー（401）の場合、トークンが無効である旨のメッセージが表示される
15. 存在しないユーザー名（404）の場合、その旨のメッセージが表示され、例外が出ない
16. 通信エラーが起きた場合、エラーメッセージが表示され、画面が操作可能なまま残る
17. リポジトリが 0 件の場合、その旨のメッセージが表示され、例外が出ない
18. 100 件を超えるリポジトリがある場合、2 ページ目以降も取得される
19. `docs/walkthrough.md` に、起動から一覧描画までの処理の流れが順序立てて記録されている
20. `docs/modules.md` に、`src/` 配下の各ファイルの役割と公開関数が記録されている
21. 主要な技術選定について `docs/decisions/` に決定記録がある
