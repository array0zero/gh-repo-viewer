# Issue #3: 見た目の改善

## 範囲と仕様の優先順位

既存のダーク配色を活かして、余白・境界・文字の階層を整理する。
この仕様は見た目について v2 の「UI の再設計、見た目の改善は非目標」を置き換える。
機能は v2 を優先し、変更のない部分は v1 に従う。

- ヘッダー、取得設定、検索操作、取得結果を余白と境界線で区切る。
- カードは名前・公開区分、説明、メタデータの順とし、同じ行のメタデータを下端に揃える。
- 幅720px以下では取得フォーム・検索操作・カードを1列にする。
- 操作要素の高さを44px以上にし、キーボードフォーカスを明示する。
- エラー、補足、取得状態が判読できる配色を用いる。
- 取得・検索・フィルタ・並び替え・キャッシュ・API関連の挙動は変更しない。
- フッターは `gh-repo-viewer v{version}`（`package.json` の `version`）を表示し、既存の11px・中央揃え・配置を維持する（Issue #5）。

## 受入条件

1. `npm run build` と `npm test` が成功する。
2. 取得フォーム、検索、言語、並び替え、取得件数、API残回数とカードの全項目が維持される。
3. デスクトップではカードが2列、幅720px以下では1列になる。
4. 幅320pxでも操作欄・長いリポジトリ名・説明・メタデータが横にはみ出さず折り返される。
5. フォーカス、無効状態、エラーが識別でき、フッターの指定を維持する。
